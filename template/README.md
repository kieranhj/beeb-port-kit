# beeb-port-kit template

The smallest BBC Micro program that exercises every piece of the kit, proven to boot in jsbeeb.
MIT, Kieran Connell. Copy this directory to start a port; `../PORTING.md` is the layer plan it
is Layer 0 of.

## What it is

A MODE 1 screen: a 4-row static status panel above a 16-row play strip, drawn as a **two-cycle
CRTC rupture** from the game's own IRQ1V handler (System VIA T1 + VSync), frame-locked at 25 Hz
(`FRAME_LOCK = 2`), **with a palette for each cycle - the panel in black, red, yellow and white,
the strip in blue, magenta, cyan and green, so all eight MODE 1 colours are on screen at once**
(decision 4). The switch is sixteen ULA writes against 48 cycles of horizontal blanking, so it
straddles a line boundary; the panel's last scanline is kept blank to hide it, and `T1_TUNE2` is
its measured phase. Keys are read straight off the keyboard matrix; **Z and X scroll the strip**
left and right by moving the CRTC start address round the **10K hardware wrap**. The panel image
(2,560 bytes, a generated pattern of coloured bars) is the one data file: it ships
ZX02-compressed and is loaded and unpacked by the kit's loader and depacker. The build stamps
itself into `INFO`, a disc file - the build time, every flag that is on, the version line on a
release - which `*TYPE INFO` reads back at any prompt; the boot shows it too.

Geometry is Paradroid's - panel at `&4A00`, strip `&5800-&7FFF` with the 10K wrap, `R1 = 80`,
16 displayed rows - because its timing was measured for it; the frame shape is Edge Grinder's
two cycles. Baseline machine is a **BBC Model B** with sideways RAM (the template itself uses no
bank); `MASTER=1` builds the Master 128 path. Nothing else: no sprites, no data pipeline, no
sound.

## Build

```powershell
.\build.ps1             # assemble into build/, then tools/make_disc.py
.\build.ps1 -Release    # every DEBUG_ flag off; the version line in the stamp
.\build.ps1 -Master     # MASTER=1
.\build.ps1 -Run        # and launch b2 on the image (-Beebjit for beebjit)
make                    # the same on any POSIX make: make release, make master, make run, make help
```

The assembler is [Baron](https://github.com/waitingforvsync/baron) 0.3.0, found through
`$BARON`, then `bin/`, then the PATH. On Windows, put this machine's paths in `local.ps1`
(gitignored), which `build.ps1` runs first. The ZX02 compressor is built from
`tools/zx02src/`, which needs a C compiler once. `RELEASE` and `MASTER` are `-D` symbols and
every build passes both. `tools/build_stamp.py` writes `build/build_time.6502` for the stamp
because Baron has no `TIME$`. It uses the last commit's time rather than the clock, so
`make` and `build.ps1`, on any machine, produce the same image with the same printed `sha256`.
`../docs/build-portability.md` has the rules.
`../docs/toolchain-baron.md` says why Baron and what it changed. Everything lands in `build/`:
`game-raw.ssd` (Baron's, **not bootable**), `game.ssd` (hand this one to an emulator - it is not
padded, and does not need to be), `game.lst`. `src/data/panel.bin` is generated by `tools/export_panel.py` and
committed.

Boot `build/game.ssd` in jsbeeb as `B-DFS1.2` (or `Master` for the `-Master` build): the
panel and strip appear, Z/X scroll.

## Examples

`examples/vscroll/` is a second, self-contained program on the same geometry: **the play strip
FIRST and smooth-scrolled one scanline at a time under the cursor keys, with the panel below it**
- Rich Talbot-Watkins's frame shape, which is what a scanline vertical scroll wants and the
opposite order to the template's. It runs at **50 Hz** (`FRAME_LOCK = 1`, a take every field),
where the template locks to 25. It has its own `build.ps1` and its own buffer oracle, and
`docs/vertical-scroll.md` has the frame, the `T1_PHASE` sweep that measured the one
scanline-exact write, and the numbers (0 of 10,240; 0 of 38,400; 0 wrong of 19,840 pixels fetched
by the vertical total adjust; 39,936 cycles a field). Read it before designing a frame that
scrolls vertically - putting the panel on top costs two visible gaps and three extra timer fires.

```powershell
cd examples\vscroll ; .\build.ps1 ; .\build.ps1 -Run
```

## What to change first

1. **The name.** `Game` in `main.6502`'s `Game` section (its `filename`), `BOOT_FILE_TAIL` in
   `!BOOT`, the title in `BUILD_STAMP`, and `tools/make_disc.py`'s `LAYOUT`;
   the disc title and file stem in `build.ps1` and the `Makefile` (`TITLE`/`STEM`; keep the
   stem lowercase).
2. **The geometry**, if the original's panel is not 4 rows or its play area is not 320 x 128:
   the constants block at the top of `src/main.6502`, and then **re-measure the T1 constants**
   (`docs/layer-0-toolchain.md` says how), **and `T1_TUNE2` with them** - the palette switch's
   phase moves with anything in the IRQ path. Read `../docs/hardware-facts.md` "Write windows" and
   "The display window and the hardware wrap" before moving anything.
3. **The panel.** Replace `tools/export_panel.py` with the exporter for the original's artwork
   (Layer 1 in `../PORTING.md`); keep it writing 4 x 640 bytes or change `PANEL_ROWS`, and
   **keep its last scanline all logical 0** while the two-palette split is in - it is the line
   the switch straddles.
4. **The keys.** `KEY_LEFT`/`KEY_RIGHT` are measured internal numbers (Z 97, X 66). Measure any
   others with OSBYTE 121; do not recall them.

Then follow the layers in `../PORTING.md` §4, one at a time, each visible in the emulator before
the next. `PLAN.md` here is seeded with them.

## Layout

| | |
|---|---|
| `src/main.6502` | constants, zero page, boot, the main loop, `setup_display`, `fill_play`, the five sections that become files, the `BUILD_STAMP` macro behind `INFO` and `!BOOT` |
| `src/rupture.6502` | the two-cycle rupture: the VSync hook (panel palette) and the three T1 fires (fire 2 is the play palette) |
| `src/lib/` | the kit's six files, forked (headers kept; each says it is a fork) |
| `src/data/panel.bin` | generated by `tools/export_panel.py`, committed |
| `tools/` | `export_panel.py`, `make_disc.py` on the forked `dfs.py` and `zx02.py`, `listing.py` (symbols and the opcode stream out of `build/game.lst`), `verify_dynamic.mjs` (boot the disc and measure the field counter, the frame lock and the scroll), `build_stamp.py` (the stamp's time and the flags, rewritten only when they change), `zx02src/` (the vendored compressor); `probe_shot.mjs` and `scan_png.py`, the headless-jsbeeb screenshot and pixel scan that measured `T1_TUNE2` |
| `examples/vscroll/` | the smooth VERTICAL scroll, play area first: its own `src/`, `build.ps1` and `tools/verify_vscroll.mjs` |
| `docs/` | `decisions.md`, `layer-0-toolchain.md` (what was measured), `vertical-scroll.md` (the example, measured), `memory-map.md` |
| `CLAUDE.md`, `PLAN.md`, `BUGS.md` | the working documents, seeded |
| `.mcp.json` | the jsbeeb MCP, so the emulator is a tool from the first session |
